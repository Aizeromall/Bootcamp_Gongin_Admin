# 매니저 교육

작성 일 : 2026-10-27 / 작업자 : 양태건

Figma `ERAsXFiMYIYBHiYxFsjJd8`의 `3:32` 화면을 기준으로 본사 메뉴에 교육 목록·상세·개설·이수 처리를 구현했습니다. Riverpod으로 로그인 담당자별 조회와 저장 상태를 관리합니다.

## API와 저장 방식

- `GET /education/courses`: 교육과 대상 매니저, 이수 현황 조회
- `GET /education/managers`: 재직 중인 매니저 부서 직원 조회
- `POST /education/courses`: 교육 개설과 대상 배정
- `POST /education/completion/{training_seq}`: 해당 배정의 이수 처리. 요청은 `{"completed":true}`이며 반복 요청에도 이수 상태를 유지합니다.

모든 경로는 본사 Bearer 토큰과 현재 재직 여부를 검증합니다. 본사 로그인 응답에 서명 토큰을 추가했고, 매니저 토큰과 역할을 구분합니다.

기존 `training` 테이블을 사용하며 테이블·컬럼 추가나 자동 마이그레이션은 없습니다. 교육 개설 시 대상 매니저마다 한 행을 저장하고, 공통 교육 ID로 묶습니다. `t_detail`에는 `_education:1`, `course_id`, `title`, `category`, `format`, `scheduled_at`, `duration_minutes`, `location`, `instructor`, `description`을 JSON으로 저장합니다. `t_date`에는 한국 시간 기준 날짜를, `t_state`에는 이수 여부를 저장합니다. 기존 일반 문자열 기록은 별도의 과거 교육으로 읽고 덮어쓰지 않습니다.

API 코드의 INSERT·UPDATE는 사용자가 개설·이수 버튼을 실행할 때 수행됩니다. 개발 과정에서는 실제 DB 구조·데이터를 변경하지 않았습니다.

## 디자인과 지원 범위

남색 사이드바, 교육 목록과 상세의 분할 배치, 상태 배지, 카드와 이수 표를 적용했습니다. 작은 화면에서는 목록과 상세를 전환합니다. 담당 종목과 평가 이력은 아래 기존 조회 API로 연결하며, 재교육은 특정 매니저를 선택한 개설 창으로 이어집니다.

| Figma 항목 | 현재 연결 |
| --- | --- |
| 담당 종목 | `GET /approval/grounds/managers`의 배정과 `GET /match/ground`의 종목을 구장 코드로 연결합니다. 두 목록 요청을 공유하고 매니저별로 반복 조회하지 않습니다. 종목 미기록·배정 없음·조회 실패를 구분합니다. |
| 본사 평가 | `GET /management/managers/{m_id}`의 `evaluates` 날짜와 평가 원문을 버튼을 열 때 조회합니다. 월별 등급 필드가 없으므로 문자열에서 C·D 등급을 추측하지 않습니다. |
| 재교육 배정 | 평가 이력 또는 대상 매니저 버튼에서 개설하면 해당 매니저만 미리 선택합니다. 실제 저장은 기존 `POST /education/courses`에 `category: 재교육`, 선택된 `manager_ids`로 요청합니다. 현재 배정 가능 명단에서 빠진 ID는 제출을 막고 선택 초기화를 제공합니다. |
| 받은 신고 | 현재 `/report/list`의 신고 대상은 회원이며, 경기 담당 매니저를 신고 대상으로 간주할 수 없습니다. 매니저별 받은 신고 수를 계산하거나 0건으로 표시하지 않았습니다. |
| 자동 재교육 추천 | 월별 평가 등급·매니저별 받은 신고 집계가 없어 자동 추천은 구현하지 않았습니다. 평가 원문을 확인한 뒤 담당자가 재교육을 개설할 수 있습니다. |
| 미이수자 알림 | 발송 API와 전달 결과 계약이 없어 발송 버튼·발송 성공 표시를 추가하지 않았습니다. |

이번 보완은 Flutter 모델·서비스·Riverpod·교육 위젯과 Mock 테스트만 수정했습니다. Python 및 실제 DB는 변경하지 않았습니다. 배정 정보와 평가 원문 조회의 기존 인증 계약은 유지하며, 이 조회 경로까지 교육 API의 본사 서명 검증을 추가한 것은 아닙니다.

첨부 관리자 화면 스타일을 본사 메뉴의 공통 사이드바에도 적용했습니다. 기존 회원·매니저·문의·구장·신고 메뉴와 연결 동작을 유지하며, 구현되지 않은 메뉴나 임의 집계는 추가하지 않았습니다. 교육 표는 넓은 화면에서 카드 폭을 채우고 작은 화면에서는 가로로 스크롤합니다. 최근 Figma 재조회는 Starter 호출 한도로 차단되어, 앞서 같은 노드에서 확보한 디자인 컨텍스트와 스크린샷을 사용했습니다.

## 확인 방법

백엔드의 새 라우터가 반영되도록 사용 중인 실행 방식으로 서버를 다시 시작한 뒤 본사 계정으로 다시 로그인합니다. 기존 로그인 세션에는 새 본사 토큰이 없습니다. Flutter의 기존 `API_BASE_URL` 설정을 그대로 사용합니다.

실제 개설·이수 버튼은 DB에 저장하므로 담당자가 의도한 교육과 대상인지 확인한 후 실행해야 합니다. 이번 검증은 HTTP Mock과 DB Mock 테스트 및 Mock 화면 렌더링으로 수행했습니다. 실제 서버·기기 연동은 별도 확인이 필요합니다.
