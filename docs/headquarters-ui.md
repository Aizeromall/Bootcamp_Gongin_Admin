# 본사 프론트엔드 연결

작성 일 : 2026-10-27 / 작업자 : 양태건

첨부한 관리자 대시보드의 남색 사이드바·밝은 배경·흰 카드·상태 배지를 기존 Flutter 앱에 적용했습니다. 새 본사 로그인은 대시보드에서 시작하며, 작은 화면에서는 하단 메뉴 선택기로 모든 본사 메뉴에 접근합니다. 경기매니저의 내 매치·지난 매치 메뉴는 기존 역할 분기를 유지합니다.

## 실제 API 연결

| 화면 | API와 범위 |
| --- | --- |
| 대시보드 | 문의 목록의 원글·후속 문의 미답변 수, 신고 `pending_count`, 이의신청 `pending_count`, 교육 `required_pending`, 팀 `total`을 표시합니다. 집계 실패는 0건으로 바꾸지 않고 재시도를 제공합니다. |
| 공지 | `GET /announce/admin`의 검색·분류·20건 페이지 처리, `POST /announce/write`의 JSON 작성. 작성자는 현재 본사 ID이며 분류·복수 대상을 선택합니다. 목록에는 서버가 허용한 본사 대상 공지만 표시됩니다. 예약 게시 API는 없습니다. |
| 제재·이의신청 | `GET /appeal/list`, `/appeal/sanction`, `/appeal/detail/{a_seq}`, `POST /appeal/review/{a_seq}`. 종목과 상태를 필터링하고 현재 본사 ID로 재심의를 시작합니다. 인용·기각·제재 철회 동작은 추가하지 않았습니다. |
| 팀 | `GET /management/teams`의 팀명·팀장 검색과 종목 필터, `/management/teams/{t_id}`의 팀원·전적·최근 결과. 없는 등급·승률을 계산하지 않습니다. |
| 매치 관리 | `GET /approval/grounds/managers`에서 담당자를 선택한 뒤 `/match/list/{m_id}`의 예약자별 내역을 조회합니다. 예약 행 수를 경기 수로 부풀리거나 본사 전체 진행률로 표시하지 않습니다. |
| 매니저 평가 | 동일 담당자 선택 후 `GET /management/managers/{m_id}`의 `evaluates` 이력을 표시합니다. 평가 작성·등급 수정은 지원 API가 없습니다. |
| 품의 작성 | `/approval/templates`, `/approval/approvers`, `/approval/vacation/deputies`, `/match/ground`, `/approval/contracts`, `/approval/grounds/owners`, `/approval/grounds/managers`를 사용합니다. 휴가·신규 계약·재계약·해지 데이터를 `POST /approval/requests`로 상신합니다. 기존 양식이 없으면 새 양식을 임의 생성하지 않습니다. |
| 품의 내역 | `GET /approval/requests`는 같은 문서의 여러 결재 행을 반환하므로 결재 기록 목록으로 표시합니다. 문서 상세는 `/approval/requests/{m_code}`, 승인·반려는 `POST /approval/requests/{m_code}/sign`을 사용합니다. 권한·단계·휴가 대리 판단은 서버가 수행합니다. |
| 신규 구장 사진 | 파일 선택 후 multipart `POST /approval/ground-photos/draft`에 `h_id`, `file`을 전달하고 반환된 파일명을 품의 내용에 첨부합니다. 서버가 허용한 JPEG/PNG/WebP, 10MB 이하, 최대 20장입니다. 첨부에서 제외한 임시 파일의 서버 삭제 API는 없습니다. |

원래의 회원·매니저·문의·구장·신고·교육 화면을 유지합니다. 매출 전용 API와 본사 전체 경기 집계 API가 없어 해당 메뉴·임의 수치를 만들지 않았습니다. 대시보드의 처리할 일은 조회된 유형별 최대 3건의 미처리 항목을 보여 주고 해당 메뉴로 이동합니다. 샘플 화면의 숫자·이름·공지 문구는 운영 데이터로 하드코딩하지 않았습니다.

## 상태와 오류 처리

서버 조회는 담당자와 URL을 키로 한 Riverpod provider를 사용하며 공통 OperationsApi의 주소·토큰·오류 해석을 공유합니다. 저장 중 중복 제출을 차단하고, 실패하면 입력을 보존합니다. 저장 성공 시 관련 목록·상세·대시보드 데이터를 갱신합니다. 기존 문의·신고·교육 변경도 공통 조회 무효화를 통해 대시보드에 반영합니다. 계정·역할이 바뀌면 대시보드 선택을 초기화합니다.

신규 계약의 소유주·구장·사진·요일별 매니저 배정을 입력할 수 있습니다. 계약 품의는 서버의 영업팀 규칙을 따릅니다. 승인 시 실제 업무 데이터가 반영되는 기존 API이므로 프론트가 서버 성공 전에 승인 완료를 표시하지 않습니다. 기존 API의 인증 방식은 변경하지 않았으며, 모든 라우터가 새 토큰 인증을 수행한다고 보장하지 않습니다.

## 검증과 실행

이번 작업에서는 Python·실제 MySQL·실제 서버 상태를 변경하지 않았습니다. HTTP/DB 연결 없는 Mock 테스트로 조회·오류 재시도·작성 실패 보존·중복 제출·재심의 시작·품의 상신과 승인·담당자별 예약 및 평가 조회를 확인했습니다. 1180×820, 390×820 크기의 Mock 화면을 렌더링했습니다.

기존 실행 설정의 `API_BASE_URL`로 서버를 지정해 앱을 재실행한 뒤 본사 계정으로 로그인합니다. 실제 양식·직원·소유주·매니저 데이터의 존재 여부, 실제 사진 선택/업로드, 서버 권한 거절과 저장 결과는 사용자 환경에서 확인해야 합니다. 개발 검증 중 실제 쓰기 요청은 실행하지 않았습니다.

## 2026-10-28 전체 관리자 목업 반영

사용자가 관리자 저장소 적용을 선택하여 회원 앱은 수정하지 않았습니다. 로그인은 남색 소개 영역과 흰 입력 영역으로 나누며, 기존의 통합 로그인과 서버 역할 판단을 유지합니다. 샘플 계정·비밀번호·역할 선택 탭은 추가하지 않았습니다.

회원·매니저·문의·팀·이의신청·품의 내역을 넓은 화면에서 목록/상세로 나눠 표시합니다. 작은 화면은 목록 선택과 복귀를 사용합니다. 매니저별 예약·평가 조회에도 좌측 담당자 목록을 제공합니다. 화면 전환 방식이 바뀌어도 기존 ID와 API 계약을 유지합니다.

문의 답변은 `POST /inquiry/answer`의 Form 계약을 공통 서비스·Riverpod 변경 상태로 옮겼습니다. 실패 시 답변 내용을 유지하고 재시도하며, 성공 후 목록·상세·대시보드를 갱신합니다. 카드의 펼침 영역에는 Material 표면을 제공하고, 알려진 표시명만 사용해 내부 컬럼명이 UI에 노출되지 않도록 했습니다.

경기매니저도 남색 사이드바와 담당자 영역을 공유합니다. 매치 목록에는 예약 요약을 함께 표시하고 경기 운영은 기존 전체 화면 흐름으로 엽니다. 실시간 기록은 어두운 점수판·선수 목록·두 열 기록 버튼으로 구성하며 기존 출석·팀 배정·시간·기록 취소·부상·결과 등록 API는 유지합니다. `내 평가`는 로그인한 본인 ID의 `/management/managers/{m_id}` 평가 원문만 조회합니다. 등급·출석률·신고 집계를 추측하지 않습니다.

첨부 목업의 매출과 매니저별 담당 팀·팀 경기 운영은 해당 업무에 맞는 API/권한 계약이 없어 추가하지 않았습니다. 본사 전체 팀 조회를 매니저 담당 팀 목록으로 바꾸어 표시하지 않습니다. 이미지의 예정 푸시·알림·월별 평가 등급·자동 재교육 추천 역시 실제 지원 범위와 구분합니다.

검증은 Mock 데이터 기반 위젯 테스트와 1180×820 로그인·회원·문의·실시간 기록 화면 렌더링으로 수행했습니다. 작은 화면의 목록 복귀와 경기 기록 버튼도 테스트했습니다. 이번 작업에서 Python·실제 DB·서버 프로세스를 변경하지 않았습니다. 실제 서버·기기·사진 선택과 저장은 별도 확인 대상입니다.

## 팀경기매치 메뉴

2026-10-28 사용자 선택에 따라 경기매니저 메뉴를 `내 매치 / 지난 매치 / 팀경기매치 / 내 평가`로 구성했습니다. `팀경기매치`를 선택하면 조회 준비 안내를 표시하며, 데이터 조회 요청이나 새 API를 추가하지 않았습니다. 본사의 `팀 관리` 메뉴는 기존 기능을 유지합니다. 팀 경기 결과 연동은 보류 상태입니다.
