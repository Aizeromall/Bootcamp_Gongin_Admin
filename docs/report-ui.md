# 본사 신고 관리 화면

작성 일 : 2026-10-27 / 작업자 : 양태건

## 반영 범위

사용자 승인에 따라 현재 브랜치에 `origin/main`의 `324587b`까지 fast-forward 병합했습니다. 기존 API를 가져온 병합 외에 Python 코드를 직접 수정하지 않았고, 실제 DB 조회·쓰기·마이그레이션·서버 재시작은 실행하지 않았습니다.

참고 URL의 `#hqReports` 화면은 웹 도구에서 접근할 수 없었고 브라우저 제어 권한도 없어 확인하지 못했습니다. 따라서 기존에 제공된 관리자 목업의 네이비 메뉴·밝은 카드·파란 선택 강조를 기준으로 작성한 UI입니다. 링크와 완전히 동일한 디자인으로 검증한 결과는 아닙니다.

## 연결한 API

| 화면 동작 | API | 처리 |
| --- | --- | --- |
| 목록·집계·필터 | `GET /report/list` | 선택한 `state`, `sport` 전송 |
| 상세·피신고자 이력 | `GET /report/detail/{r_seq}` | 신고 ID로 상세 조회 |
| 심의 시작 | `POST /report/review/{r_seq}` | JSON `h_id`에 로그인한 본사 직원 ID 사용 |

상태 탭 건수는 종목 필터를, 종목별 건수는 상태 필터를 반영하는 서버 응답을 사용합니다. 처리 대기 건수는 서버가 반환한 전체 대기 건수입니다. 클라이언트에서 임의로 집계를 만들지 않습니다.

## 화면과 상태

- 본사 대시보드에만 신고 관리 메뉴를 추가했습니다.
- 넓은 화면에서는 목록과 상세를 나란히, 좁은 화면에서는 목록 선택 후 상세와 목록 복귀 버튼을 표시합니다.
- 처리 상태·종목 필터, 상황 설명·관련 경기 정보, 첨부 자료 목록, 피신고자의 누적 경고·받은 신고·계정 상태를 표시합니다.
- 첨부 자료는 API에서 반환한 문자열 목록을 선택·복사할 수 있게 표시합니다. 파일 다운로드/이미지 제공 경로를 가정하지 않습니다.
- 데이터에 없는 이력 수치는 0을 만들지 않고 미확인 상태로 표시합니다.
- 필터·담당자를 키로 Riverpod provider를 분리했습니다. 이전 필터 요청의 늦은 응답이 현재 결과를 덮어쓰지 않습니다.
- 심의 요청 상태도 담당자·신고별로 분리합니다. 저장 중 중복 제출을 막고 성공 후 목록·상세를 갱신합니다. 409 충돌 시 상세와 목록을 재조회하며 쓰기는 자동 재전송하지 않습니다.
- 로딩·빈 목록·오류를 구분하고 사용자가 직접 재시도할 수 있습니다.

현재 백엔드는 심의 시작만 지원합니다. 기각·제재 확정·처리완료 등록·신고자 알림 발송은 구현한 기능으로 표시하지 않습니다. 관련 기능을 추가하려면 별도 API 검토와 승인이 필요합니다.

## 검증과 사용자 확인

Mock API 기반 위젯/상태 테스트로 목록·필터·빈 결과·오류 재시도·심의 시작·중복 제출 방지·충돌 재조회·작은 화면·본사 전용 메뉴·필터/계정별 캐시 분리를 검증합니다. 실제 DB에 쓰는 Python 통합 테스트는 실행하지 않습니다.

```sh
flutter test
flutter analyze
```

현재 실행 중인 서버가 병합 전 코드라면 사용자가 서버를 재시작한 뒤 앱을 실행해야 신고 API가 연결됩니다. 앱에서 본사 계정으로 로그인하고 신고 관리 메뉴를 선택하여 실제 데이터·첨부 경로·필터와 폰트·키보드·화면 크기별 배치를 확인해 주세요. Mock 검증은 실제 서버와 기기 확인을 대체하지 않습니다.
