# 경기 진행 기능

작업자 : 양태건  
수정일 : 2026-10-26

## 실행

백엔드 의존성이 설치된 Python 환경에서 관리자 프로젝트 루트를 기준으로 실행합니다.

```sh
python python/main.py
```

새 테이블은 필요하지 않습니다. 사용자가 추가한 `c_result_record.c_r_r_injury`를 사용하며, 상세 부상 내용을 담기 위해 해당 컬럼을 `VARCHAR(50)`에서 `TEXT NOT NULL`로 확장했습니다. 삭제한 경기 관리·로그인 세션 테이블을 참조하지 않으며 테이블 생성용 마이그레이션 파일도 제거했습니다. 다른 DB에 반영할 때는 `python/migrations/20261026_injury_column.sql`의 기존 컬럼 확장만 적용합니다.

서버를 재시작하고 Flutter 앱을 핫 리스타트한 뒤 매니저 계정으로 다시 로그인합니다. 기존 로그인 상태에는 새 인증 토큰이 없습니다. 토큰은 12시간 유효하며 DB를 사용하지 않고 HMAC-SHA256 서명으로 검증합니다. 기본 개발 설정에서는 서버 재시작 시 토큰이 무효화됩니다. 경기 진행 상태를 메모리에 보관하므로 서버는 단일 프로세스로 실행해야 합니다. 기본 설정은 단일 프로세스입니다.

## 사용 흐름

1. **내 매치**에서 같은 구장·날짜·시작 시간으로 묶인 경기를 선택합니다.
2. 모든 예약자를 출석 또는 결석으로 확인합니다. 팀 배정 전까지 정정할 수 있습니다.
3. **경기 시작 · 팀 설정**으로 이동하여 출석자를 A/B팀에 배정하고 팀명·조끼 색을 지정합니다. 두 팀은 모두 1명 이상, 인원 차이는 1명 이하여야 합니다. **출석으로 돌아가기**로 출석을 정정할 수 있습니다.
4. **경기 시작** 후 선수를 선택하고 골·도움·슈팅·경고·퇴장을 입력합니다. 골은 해당 팀 점수에도 반영됩니다. **마지막 기록 취소**로 개인 기록과 점수를 함께 되돌릴 수 있습니다. 퇴장한 선수는 추가 기록을 입력할 수 없으며 퇴장 기록 취소로 복원할 수 있습니다.
5. **응급 · 부상 기록**에서 부위·정도·조치·상황·접촉 여부를 저장합니다. 부상 발생 시각은 입력 창을 연 시각을 사용합니다. 조치에 경기 일시 중단을 선택하면 타이머도 정지합니다. 이 입력은 실제 신고·이송·연락을 자동 실행하지 않습니다.
6. **경기 종료** 후 결과를 확인합니다. **기록으로 돌아가기**에서는 시계를 정지한 상태로 정정할 수 있습니다.
7. **결과 등록**은 모든 회원의 결과를 한 트랜잭션으로 저장하고 결과 존재 여부를 기준으로 **지난 매치**로 이동합니다. 완료 후에는 수정할 수 없으며 재전송으로 중복 결과를 만들지 않습니다.

## 저장과 권한

- 서버 메모리: 팀 배정·색상, 진행 단계, 타이머, 개인 이벤트. 서버가 실행 중이면 화면을 다시 열어 복원할 수 있습니다. 서버 재시작 시 미등록 진행 상태는 사라집니다. 부상은 아래 기존 컬럼에 즉시 저장합니다. 팀 설정 화면의 미저장 선택은 경기 시작 시 메모리에 반영됩니다.
- `c_result_record`: 출석 시 행을 생성하고 결과 등록 시 같은 회원·경기의 행에 최종 결과를 반영합니다. 별도 결과 행을 추가하여 중복시키지 않습니다. 서버를 재시작해도 출석·팀명·최종 점수·개인 통계는 복원합니다. 경기 소요 시간·이벤트 발생 시각·조끼 색은 별도 항목이 없어 복원하지 않습니다.
- `c_r_r_injury`: 부상 저장 시 해당 회원·경기의 결과 행에 JSON 배열로 즉시 누적합니다. 부위·정도·조치·설명·접촉 여부·발생 시각을 보관합니다. 부상 없는 신규 행에는 빈 문자열을 저장하고, 기존 일반 텍스트도 조회 시 보존합니다. 결과 등록 전과 서버 재시작 후에도 다시 조회할 수 있습니다.
- `c_r_r_statcode`: `G:1,A:0,S:2,Y:0,R:0` 형식. G=골, A=도움, S=슈팅, Y=경고, R=퇴장입니다. `e_code`는 기존 API와 같은 `SOCCER`, `c_r_r_score`는 `A팀점수:B팀점수`입니다.
- 매니저 로그인은 `match_manager.m_department`가 `매니저`인 계정만 허용하며, 본사 로그인은 별도 `headquarter` 테이블에서 확인합니다. 새 `/match/operations` API는 매니저 로그인 토큰을 요구합니다. 요청 경로의 임의 아이디가 아닌 토큰에 연결된 매니저의 구장·배정 요일·시작 시간으로 확인합니다. 이미 진행을 맡은 다른 매니저의 경기에는 진입할 수 없습니다.
- `assign.a_day`는 `월,수,금`, `a_time`은 `18:00~22:00` 형식을 해석합니다. 해석할 수 없는 배정은 허용하지 않습니다.
- 동시 조작은 서버의 version으로 검증합니다. 오래된 화면에서 요청하면 다시 불러오도록 안내합니다.
- 현재 진행 화면은 축구를 지원합니다. 다른 종목의 골·점수 규칙, 자동 푸시, MVP, 본사 부상 보고 전용 화면은 포함하지 않습니다. 기존 방식으로 결과가 이미 등록된 경기는 지난 매치로 분류하며 원본 점수·스탯을 읽기 전용으로 표시합니다. 새 진행 상태나 결과 행을 생성하지 않습니다.

## 검증

```sh
flutter test
python -m unittest discover -s python/tests -v
python python/tests/integration_match_flow.py
```

마지막 명령은 개발 MySQL에 임시 경기·회원·예약을 생성하여 실제 HTTP 흐름을 검증하고 마지막에 전부 롤백합니다. 기존 구장과 배정 정보가 각각 한 건 이상 필요하며, DDL을 실행하거나 실제 경기 결과를 확정하지 않습니다.
